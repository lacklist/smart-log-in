# Session Workspace — облачный пилот

Расширение Chrome/Chromium и API для закрытого пилота на Windows и Linux. API хранит отдельный зашифрованный снимок на кабинет; шифрование и расшифровка выполняются расширением. В комплект входят PostgreSQL, HTTPS через Caddy и Docker Compose.

## Что делает расширение

1. Вы входите в Google, VK и/или СДО РТУ МИРЭА обычным способом на исходном устройстве.
2. Расширение собирает cookie выбранных сервисов, шифрует их мастер-паролем прямо в браузере и отправляет зашифрованный блок на ваш сервер.
3. На другом устройстве вы входите в тот же кабинет, вводите мастер-пароль — расширение скачивает блок, расшифровывает и восстанавливает cookie.
4. Переключатели в интерфейсе позволяют выбрать, в какие сервисы авторизоваться, а в какие нет. Настройки сохраняются между сессиями.

Сервер видит только зашифрованный блок — мастер-пароль никогда не покидает браузер.

## Что нужно для запуска

- Linux VPS с публичным IPv4/IPv6, минимум 2 ГБ RAM и 20 ГБ диска.
- Домен или поддомен, DNS `A`/`AAAA` которого указывает на VPS.
- Открытые входящие порты TCP 80/443 и UDP 443.
- Docker Engine с Docker Compose plugin.
- Chrome/Chromium на клиентских устройствах.

## Развёртывание на VPS — пошагово

### 1. Подготовка файлов

Скопируйте всю папку проекта на VPS, например в `/opt/session-workspace`:

```bash
scp -r ./session-workspace user@your-vps:/opt/session-workspace
```

### 2. Создание `.env`

На VPS создайте `.env` из `.env.example` и заполните значения:

```bash
cd /opt/session-workspace
cp .env.example .env
chmod 600 .env
```

Сгенерируйте секреты прямо на VPS:

```bash
echo "POSTGRES_PASSWORD=$(openssl rand -hex 32)"
echo "REGISTRATION_INVITE_CODE=$(openssl rand -hex 32)"
```

Вставьте сгенерированные значения в `.env`. Укажите ваш домен в `DOMAIN`.

### 3. Загрузка расширения и получение ID

1. Откройте `chrome://extensions` в Chrome/Chromium.
2. Включите режим разработчика.
3. Нажмите «Загрузить распакованное расширение» и выберите папку проекта (где лежит `manifest.json`).
4. На карточке расширения скопируйте ID вида `abcdefghijklmnopqrstuvwxyzabcdef`.
5. Вставьте ID в `.env`:
   ```
   ALLOWED_ORIGINS=chrome-extension://<ВАШ_ID>
   ```
   Если расширение загружено на нескольких устройствах с разными ID, добавьте все через запятую.

### 4. Запуск сервера

```bash
docker compose up -d --build
docker compose ps
```

### 5. Проверка

```bash
curl https://<ваш-домен>/health
```

Должен вернуть `{"ok":true,...}`. Caddy автоматически получит и будет продлевать TLS-сертификат. Если сертификат не выдан — проверьте DNS и доступность портов 80/443.

### 6. Использование

1. В расширении укажите `https://<ваш-домен>`.
2. Создайте кабинет: введите почту, пароль кабинета (от 12 символов) и код приглашения из `.env`.
3. Задайте отдельный мастер-пароль для шифрования снимка.
4. Включите переключатели только для нужных сервисов.
5. Нажмите «Сохранить текущие сессии».
6. На другом устройстве: загрузите расширение, укажите тот же адрес сервера, войдите в кабинет, включите нужные сервисы и нажмите «Войти везде».

## Ежедневное использование

1. На исходном устройстве войдите в выбранные сервисы и завершите их проверки.
2. В расширении войдите в кабинет, включите нужные сервисы переключателями, задайте мастер-пароль и нажмите «Сохранить текущие сессии».
3. На другом устройстве загрузите расширение, укажите тот же адрес API, войдите в кабинет и нажмите «Войти везде».
4. На чужом/общем устройстве нажмите очистку, чтобы удалить локальные cookie и отключить токен кабинета.

Переключатели сервисов сохраняются автоматически — при следующем открытии расширения выбранные сервисы останутся включёнными.

## Обслуживание

Посмотреть состояние:

```bash
docker compose ps
docker compose logs --tail=100 api caddy
```

Обновить код после копирования новой версии:

```bash
docker compose up -d --build
```

Резервная копия PostgreSQL:

```bash
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backup.sql
```

Восстановление в пустую базу:

```bash
cat backup.sql | docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" "$POSTGRES_DB"'
```

## Безопасность

- Не отправляйте коды, пароли и cookie в чат.
- Секреты генерируйте только на VPS; доступ к `.env` оставьте только администратору (`chmod 600 .env`).
- Каждый кабинет имеет отдельную строку архива и отдельные серверные токены.
- Сервер сохраняет только зашифрованный блок; мастер-пароль не отправляется на сервер.
- Токен входа хранится в `chrome.storage.session` и действует до 8 часов.
- Храните резервные копии отдельно от VPS с ограниченными правами.

## Ограничения пилота

- Разрешены только Google, VK и домены `mirea.ru`; расширение не собирает cookies остальных сайтов.
- Новый снимок заменяет предыдущий снимок этого же кабинета.
- Кнопка выхода чистит cookie выбранных сервисов в текущем профиле и отзывает токен кабинета на сервере. Она не гарантирует отзыв скопированной сессии на стороне Google/VK/МИРЭА.
- Пилот не включает восстановление пароля, подтверждение почты, биллинг, админ-панель и независимый аудит безопасности.
- Сайты могут отклонить перенос cookie или снова запросить подтверждение.
- Не используйте это как способ обхода правил провайдера или политики учреждения; обладание cookie фактически даёт доступ к аккаунту.
